# 4 VERSÕES DO CURRÍCULO — blocos de troca

> **Escopo:** estas 4 variações se aplicam ao **Currículo A** (`MASTER.md`, Front-End).
> O **Currículo B** (`MASTER-B-business-systems.md`) é um documento separado e completo —
> não é uma variação. Use B para SaaS B2B, ERP, logística, manufatura, consultoria e times
> de *internal tools*; use A com estas 4 variações para todo o resto.

Tudo abaixo troca **apenas 5 elementos** do `MASTER.md`. Experiência, formação e idiomas
permanecem idênticos nas quatro versões. Nunca invente nada para encaixar numa versão.

Os 6 elementos que mudam:
1. Título (linha 2)
2. Primeira frase do Summary
3. **Ordem dos Selected Achievements** — os 2 primeiros são o que o recrutador lê de fato
4. Ordem das categorias em Core Skills
5. Ordem dos 3 primeiros bullets da experiência
6. Ordem dos projetos

## Regra de adaptação por vaga (não pule)

Para cada candidatura, faça **só isto** — leva 4 minutos:

1. Cole a descrição da vaga num documento.
2. Marque as tecnologias e termos **que você realmente tem**.
3. Escreva esses termos **exatamente como a vaga escreve** ("React.js" vs "React", "REST APIs" vs
   "RESTful APIs", "Front-End" vs "Frontend") — o ATS faz match de string, não de significado.
4. Mova esses termos para o **início** das linhas de Core Skills.
5. Se a vaga cita um termo que você **não** tem, deixe de fora. Sempre.

**Nunca** copie a descrição inteira. Currículo com 100% de match e entrevista com 40% de sustentação
é pior do que não se candidatar.
